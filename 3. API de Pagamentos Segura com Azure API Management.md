# 3. API de Pagamentos Segura com Azure API Management

Este documento detalha o processo de desenvolvimento e configuração de uma API de Pagamentos Segura utilizando o Azure API Management, conforme proposto no desafio da Digital Innovation One (DIO).

## Objetivo do Projeto

Criar uma API de pagamentos com foco em segurança, implementando autenticação JWT e aplicando boas práticas de design de endpoints, utilizando o Azure API Management para gerenciar e proteger o acesso à API.

## Etapas do Desenvolvimento

### 1. Criação do App Service

O primeiro passo foi criar um App Service no Azure para hospedar a API de pagamentos:

1. Acessei o Portal do Azure e naveguei até "App Services"
2. Cliquei em "Criar" e selecionei "Web App"
3. Configurei os seguintes parâmetros:
   - **Grupo de Recursos**: `rg-payment-api`
   - **Nome**: `payment-api-service`
   - **Publicar**: Código
   - **Pilha de runtime**: .NET 6 (LTS)
   - **Sistema Operacional**: Linux
   - **Região**: East US
   - **Plano do Serviço de Aplicativo**: Criado um novo plano Basic B1
4. Revisei e criei o recurso

Após a criação, configurei a implantação contínua conectando o repositório GitHub ao App Service, permitindo atualizações automáticas quando o código é atualizado.

### 2. Implementação de Boas Práticas de Endpoints

Para garantir uma API bem estruturada e de fácil manutenção, implementei as seguintes práticas:

#### Versionamento da API

```csharp
// Exemplo de configuração de versionamento na Startup.cs
services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;
    options.ReportApiVersions = true;
});
```

#### Nomenclatura RESTful

Defini endpoints seguindo convenções RESTful:

```csharp
// PaymentController.cs

[ApiVersion("1.0")]
public class PaymentController : ControllerBase
{
    [HttpGet]
    public async Task<ActionResult<IEnumerable<Payment>>> GetPayments() { ... }

    [HttpGet("{id}")]
    public async Task<ActionResult<Payment>> GetPayment(int id) { ... }

    [HttpPost]
    public async Task<ActionResult<Payment>> CreatePayment(PaymentRequest payment) { ... }

    [HttpPut("{id}")]
    public async Task<IActionResult> UpdatePayment(int id, Payment payment) { ... }

    [HttpDelete("{id}")]
    public async Task<IActionResult> DeletePayment(int id) { ... }
}
```

#### Respostas HTTP Adequadas

Implementei respostas HTTP apropriadas para cada operação:

```csharp
// Exemplo de método com respostas HTTP adequadas
[HttpPost]
public async Task<ActionResult<Payment>> CreatePayment(PaymentRequest request)
{
    if (!ModelState.IsValid)
        return BadRequest(ModelState);

    try
    {
        var payment = await _paymentService.ProcessPayment(request);
        return CreatedAtAction(nameof(GetPayment), new { id = payment.Id }, payment);
    }
    catch (Exception ex)
    {
        // Log do erro
        return StatusCode(500, "Erro interno ao processar pagamento");
    }
}
```

#### Documentação com Swagger

Adicionei documentação Swagger para facilitar o entendimento e teste da API:

```csharp
// Configuração do Swagger na Startup.cs
services.AddSwaggerGen(c =>
{
    c.SwaggerDoc("v1", new OpenApiInfo { 
        Title = "API de Pagamentos", 
        Version = "v1",
        Description = "API segura para processamento de pagamentos"
    });
    
    // Configuração para incluir o JWT no Swagger
    c.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
    {
        Description = "JWT Authorization header using the Bearer scheme",
        Name = "Authorization",
        In = ParameterLocation.Header,
        Type = SecuritySchemeType.ApiKey,
        Scheme = "Bearer"
    });
    
    c.AddSecurityRequirement(new OpenApiSecurityRequirement
    {
        {
            new OpenApiSecurityScheme
            {
                Reference = new OpenApiReference
                {
                    Type = ReferenceType.SecurityScheme,
                    Id = "Bearer"
                }
            },
            Array.Empty<string>()
        }
    });
});
```

### 3. Implementação da Autenticação JWT

Para proteger a API, implementei autenticação baseada em JWT (JSON Web Tokens):

#### Configuração do JWT

```csharp
// JwtConfiguration.cs
public class JwtConfiguration
{
    public string Secret { get; set; }
    public string Issuer { get; set; }
    public string Audience { get; set; }
    public int ExpirationInMinutes { get; set; }
}

// Configuração na Startup.cs
services.Configure<JwtConfiguration>(Configuration.GetSection("JwtSettings"));

var jwtSettings = Configuration.GetSection("JwtSettings").Get<JwtConfiguration>();
var key = Encoding.ASCII.GetBytes(jwtSettings.Secret);

services.AddAuthentication(x =>
{
    x.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    x.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(x =>
{
    x.RequireHttpsMetadata = false;
    x.SaveToken = true;
    x.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuerSigningKey = true,
        IssuerSigningKey = new SymmetricSecurityKey(key),
        ValidateIssuer = true,
        ValidateAudience = true,
        ValidIssuer = jwtSettings.Issuer,
        ValidAudience = jwtSettings.Audience,
        ClockSkew = TimeSpan.Zero
    };
});
```

#### Serviço de Geração de Token

```csharp
// TokenService.cs
public class TokenService : ITokenService
{
    private readonly JwtConfiguration _jwtSettings;

    public TokenService(IOptions<JwtConfiguration> jwtSettings)
    {
        _jwtSettings = jwtSettings.Value;
    }

    public string GenerateToken(string userId, string role)
    {
        var tokenHandler = new JwtSecurityTokenHandler();
        var key = Encoding.ASCII.GetBytes(_jwtSettings.Secret);
        
        var tokenDescriptor = new SecurityTokenDescriptor
        {
            Subject = new ClaimsIdentity(new[]
            {
                new Claim(ClaimTypes.Name, userId),
                new Claim(ClaimTypes.Role, role)
            }),
            Expires = DateTime.UtcNow.AddMinutes(_jwtSettings.ExpirationInMinutes),
            SigningCredentials = new SigningCredentials(
                new SymmetricSecurityKey(key), 
                SecurityAlgorithms.HmacSha256Signature),
            Issuer = _jwtSettings.Issuer,
            Audience = _jwtSettings.Audience
        };
        
        var token = tokenHandler.CreateToken(tokenDescriptor);
        return tokenHandler.WriteToken(token);
    }
}
```

#### Controller de Autenticação

```csharp
// AuthController.cs
[ApiController]
[Route("api/v{version:apiVersion}/auth")]
[ApiVersion("1.0")]
public class AuthController : ControllerBase
{
    private readonly ITokenService _tokenService;
    private readonly IUserService _userService;

    public AuthController(ITokenService tokenService, IUserService userService)
    {
        _tokenService = tokenService;
        _userService = userService;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginRequest request)
    {
        // Validação do usuário (simplificada para o exemplo)
        var user = await _userService.ValidateUser(request.Username, request.Password);
        
        if (user == null)
            return Unauthorized(new { message = "Usuário ou senha inválidos" });

        // Geração do token
        var token = _tokenService.GenerateToken(user.Id, user.Role);
        
        return Ok(new
        {
            token,
            expiresIn = 60 // minutos
        });
    }
}
```

### 4. Configuração do Azure API Management

O Azure API Management (APIM) foi configurado para gerenciar, proteger e monitorar a API:

1. Criei uma instância do API Management no Portal do Azure:
   - **Nome**: `payment-api-management`
   - **Grupo de Recursos**: `rg-payment-api` (mesmo do App Service)
   - **Região**: East US
   - **Camada de preço**: Developer (para ambiente de desenvolvimento)

2. Importei a API do App Service para o APIM:
   - Utilizei a definição OpenAPI (Swagger) gerada pela API
   - Configurei o nome da API, versão e esquemas

3. Configurei políticas de segurança no APIM:

   **Política de validação JWT**:
   ```xml
   <policies>
       <inbound>
           <base />
           <validate-jwt header-name="Authorization" failed-validation-httpcode="401" failed-validation-error-message="Unauthorized. Access token is missing or invalid.">
               <openid-config url="https://login.microsoftonline.com/{tenant-id}/.well-known/openid-configuration" />
               <audiences>
                   <audience>api://payment-api</audience>
               </audiences>
               <required-claims>
                   <claim name="scp" match="any">
                       <value>payment.read</value>
                       <value>payment.write</value>
                   </claim>
               </required-claims>
           </validate-jwt>
       </inbound>
       <backend>
           <base />
       </backend>
       <outbound>
           <base />
       </outbound>
       <on-error>
           <base />
       </on-error>
   </policies>
   ```

   **Política de limitação de taxa (rate limiting)**:
   ```xml
   <policies>
       <inbound>
           <base />
           <rate-limit calls="5" renewal-period="60" />
       </inbound>
       <backend>
           <base />
       </backend>
       <outbound>
           <base />
       </outbound>
       <on-error>
           <base />
       </on-error>
   </policies>
   ```

   **Política CORS**:
   ```xml
   <policies>
       <inbound>
           <base />
           <cors>
               <allowed-origins>
                   <origin>https://trusted-domain.com</origin>
               </allowed-origins>
               <allowed-methods>
                   <method>GET</method>
                   <method>POST</method>
                   <method>PUT</method>
                   <method>DELETE</method>
               </allowed-methods>
               <allowed-headers>
                   <header>Content-Type</header>
                   <header>Authorization</header>
               </allowed-headers>
           </cors>
       </inbound>
       <backend>
           <base />
       </backend>
       <outbound>
           <base />
       </outbound>
       <on-error>
           <base />
       </on-error>
   </policies>
   ```

4. Configurei o Portal do Desenvolvedor para documentação da API:
   - Personalizei a documentação com exemplos de uso
   - Adicionei descrições detalhadas para cada endpoint
   - Configurei exemplos de requisição e resposta

## Insights e Aprendizados

Durante o desenvolvimento deste projeto, adquiri diversos conhecimentos importantes:

1. **Segurança em Camadas**: Aprendi a importância de implementar segurança em múltiplas camadas, desde o código da aplicação (JWT) até o gerenciamento da API (APIM).

2. **Boas Práticas de API Design**: A implementação de versionamento, nomenclatura RESTful e respostas HTTP adequadas melhorou significativamente a usabilidade e manutenibilidade da API.

3. **Gerenciamento Centralizado**: O Azure API Management oferece uma forma centralizada de gerenciar APIs, permitindo aplicar políticas consistentes sem modificar o código da aplicação.

4. **Monitoramento e Analytics**: A configuração de monitoramento no APIM proporcionou insights valiosos sobre o uso da API, ajudando a identificar padrões e potenciais problemas.
