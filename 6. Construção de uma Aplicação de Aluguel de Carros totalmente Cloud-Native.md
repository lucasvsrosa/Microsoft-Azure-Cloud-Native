# Construção de uma Aplicação de Aluguel de Carros totalmente Cloud-Native

## 📋 Visão Geral do Projeto

Este projeto implementa uma aplicação de aluguel de carros totalmente cloud-native utilizando a plataforma Microsoft Azure. A solução segue os princípios de arquitetura moderna, incluindo microsserviços, containerização e serverless, para criar um sistema escalável, resiliente e de fácil manutenção.

## 🏗️ Arquitetura da Solução

A arquitetura da aplicação foi projetada seguindo os princípios cloud-native e as melhores práticas da plataforma Azure:

### Componentes Principais

1. **API BFF (Backend for Frontend)**: 
   - Implementada com FastAPI (Python)
   - Containerizada e hospedada no Azure Container Apps
   - Ponto de entrada único para o frontend
   - Gerencia requisições e orquestra fluxos de negócio

2. **Azure Function - RentProcess**:
   - Função serverless acionada por mensagens na fila
   - Responsável pelo processamento de solicitações de aluguel
   - Valida disponibilidade do veículo e cria registros de aluguel

3. **Azure Function - Payment**:
   - Função serverless para processamento de pagamentos
   - Integra-se com gateways de pagamento externos (simulado)
   - Atualiza o status do aluguel após processamento

4. **Azure Queue Storage**:
   - Filas para comunicação assíncrona entre componentes
   - Garante desacoplamento e resiliência

5. **Banco de Dados**:
   - Armazenamento de dados estruturados (simulado)
   - Poderia ser implementado com Azure Cosmos DB ou Azure SQL Database

6. **Application Insights**:
   - Monitoramento e observabilidade da aplicação
   - Coleta de logs, métricas e telemetria

### Fluxo de Dados

1. O cliente interage com o frontend para selecionar um carro e solicitar aluguel
2. O frontend envia requisição para a API BFF
3. A API BFF valida a requisição e envia mensagem para a fila de processamento
4. A Function RentProcess é acionada pela mensagem na fila
5. RentProcess valida disponibilidade e cria registro de aluguel
6. Uma mensagem é enviada para a fila de pagamento
7. A Function Payment processa o pagamento e atualiza o status do aluguel
8. O cliente pode consultar o status do aluguel através da API BFF

## 🛠️ Implementação Técnica

### 1. API BFF (Backend for Frontend)

A API BFF foi implementada utilizando FastAPI, um framework moderno e de alto desempenho para Python. A escolha do FastAPI se deve à sua excelente performance, tipagem forte com Pydantic e documentação automática com Swagger.

**Principais características:**

- Endpoints RESTful para listar carros, obter detalhes e solicitar aluguel
- Validação de dados com Pydantic
- Integração com Azure Queue Storage para comunicação assíncrona
- Containerização com Docker para facilitar o deploy no Azure Container Apps

**Trecho de código relevante:**

```python
@app.post("/alugar", response_model=AluguelResponse, status_code=202)
async def solicitar_aluguel(aluguel_request: AluguelRequest):
    """Recebe uma solicitação de aluguel e a envia para processamento assíncrono."""
    carro_id = aluguel_request.carro_id
    
    # Verifica se o carro existe e está disponível
    carro_encontrado = next((carro for carro in carros_db if carro["id"] == carro_id), None)
    if not carro_encontrado:
        raise HTTPException(status_code=404, detail="Carro não encontrado")
    if not carro_encontrado["disponivel"]:
        raise HTTPException(status_code=400, detail="Carro indisponível no momento")

    # Cria a mensagem para a fila
    mensagem_dict = aluguel_request.dict()
    mensagem_str = json.dumps(mensagem_dict)
    
    try:
        # Envia a mensagem para a fila
        queue_client.send_message(mensagem_str)
        return AluguelResponse(mensagem="Solicitação de aluguel recebida e enfileirada para processamento.")
    except Exception as e:
        raise HTTPException(status_code=500, detail="Erro interno ao processar a solicitação de aluguel.")
```

### 2. Azure Function RentProcess

A Azure Function RentProcess é responsável por processar as solicitações de aluguel recebidas através da fila. Ela é acionada automaticamente quando uma nova mensagem chega à fila.

**Principais características:**

- Trigger de fila (QueueTrigger) para processamento assíncrono
- Validação da disponibilidade do veículo
- Criação do registro de aluguel
- Atualização do status do veículo
- Enfileiramento de mensagem para processamento de pagamento

**Trecho de código relevante:**

```python
def main(msg: func.QueueMessage) -> None:
    logging.info('Python queue trigger function processed a queue item.')

    try:
        # Decodifica a mensagem
        message_body = msg.get_body().decode('utf-8')
        aluguel_data = json.loads(message_body)

        carro_id = aluguel_data.get('carro_id')
        cliente_id = aluguel_data.get('cliente_id')
        dias = aluguel_data.get('dias')

        # Validação e processamento do aluguel
        carro_encontrado = next((carro for carro in carros_db if carro["id"] == carro_id), None)
        
        if not carro_encontrado or not carro_encontrado["disponivel"]:
            logging.error(f"Carro ID {carro_id} não encontrado ou indisponível.")
            return

        # Criação do registro de aluguel
        aluguel_id = str(uuid.uuid4())
        novo_aluguel = {
            "aluguel_id": aluguel_id,
            "carro_id": carro_id,
            "cliente_id": cliente_id,
            "dias": dias,
            "status": "PENDENTE_PAGAMENTO",
            "valor_total": dias * carro_encontrado["preco_diaria"]
        }
        
        # Atualização do status do carro
        carro_encontrado["disponivel"] = False
        
        logging.info(f"Processamento do aluguel ID {aluguel_id} concluído com sucesso.")

    except Exception as e:
        logging.error(f"Erro ao processar a mensagem da fila: {e}")
```

### 3. Azure Function Payment

A Azure Function Payment é responsável pelo processamento de pagamentos dos aluguéis. Ela é acionada por mensagens na fila de pagamento.

**Principais características:**

- Trigger de fila para processamento assíncrono
- Simulação de integração com gateway de pagamento externo
- Atualização do status do aluguel após processamento do pagamento
- Tratamento de erros e exceções

**Trecho de código relevante:**

```python
def main(msg: func.QueueMessage) -> None:
    logging.info("Python queue trigger function (Payment) processed a queue item.")

    try:
        # Decodifica a mensagem
        message_body = msg.get_body().decode("utf-8")
        payment_data = json.loads(message_body)

        aluguel_id = payment_data.get("aluguel_id")
        valor = payment_data.get("valor")

        # Simula chamada ao Gateway de Pagamento
        pagamento_aprovado, transacao_id = simulate_payment_gateway(aluguel_id, valor)

        # Atualiza status do aluguel no DB
        if pagamento_aprovado:
            novo_status = "PAGAMENTO_APROVADO"
        else:
            novo_status = "PAGAMENTO_FALHOU"
        
        # Atualização do status no banco de dados (simulado)
        update_success = find_and_update_rental_status(aluguel_id, novo_status)
        
        logging.info(f"Processamento de pagamento para aluguel ID {aluguel_id} concluído. Status final: {novo_status}")

    except Exception as e:
        logging.error(f"Erro ao processar a mensagem da fila de pagamento: {e}")
```

## 🚀 Configuração do Ambiente Azure

Para implantar esta solução no Azure, são necessários os seguintes recursos:

1. **Azure Container Apps**:

   - Para monitoramento e observabilidade da aplicação
   - Integrado com todos os componentes

## 📊 Benefícios da Arquitetura Cloud-Native

1. **Escalabilidade**: Cada componente pode escalar independentemente conforme a demanda.

2. **Resiliência**: O desacoplamento via filas garante que falhas em um componente não afetem os demais.

3. **Custo-eficiência**: Modelo serverless para funções permite pagar apenas pelo uso real.

4. **Manutenibilidade**: Componentes isolados facilitam atualizações e manutenção.

5. **Observabilidade**: Monitoramento centralizado com Application Insights.

## 🔍 Insights e Aprendizados

Durante o desenvolvimento deste projeto, foram obtidos diversos insights importantes:

1. **Desacoplamento via filas**: A comunicação assíncrona entre componentes via filas é fundamental para criar sistemas resilientes e escaláveis.

2. **Padrão BFF**: O Backend for Frontend simplifica a interface entre o cliente e os microsserviços, melhorando a experiência do desenvolvedor frontend.

3. **Serverless para processamento assíncrono**: Azure Functions são ideais para processamento assíncrono baseado em eventos, reduzindo custos e complexidade operacional.

4. **Containerização para serviços web**: A containerização da API BFF facilita a implantação, escalabilidade e portabilidade.

5. **Observabilidade integrada**: A integração do Application Insights em todos os componentes proporciona visibilidade completa do sistema.
