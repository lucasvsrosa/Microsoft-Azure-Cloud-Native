## Etapa 1: Criando o Grupo de Recursos (Resource Group) e o Banco de Dados SQL no Azure

A organização no Azure começa com os Grupos de Recursos (Resource Groups). Eles funcionam como contêineres lógicos para agrupar os recursos relacionados de uma solução. Para este projeto, precisamos de um Grupo de Recursos para conter nosso Banco de Dados SQL e a Conta de Armazenamento.

### Criação do Grupo de Recursos

A maneira mais programática e replicável de criar recursos no Azure é através da Azure CLI (Command-Line Interface) ou Azure PowerShell. Utilizando a CLI, o comando para criar um novo Grupo de Recursos seria semelhante a este:

```bash
# Exemplo de comando Azure CLI para criar um Resource Group
# Substitua <nome-do-grupo-de-recursos> e <localizacao> pelos valores desejados
# Ex: eastus, westus, brazilsouth
az group create --name <nome-do-grupo-de-recursos> --location <localizacao>
```

**Insight:** Escolher uma localização (região) próxima aos seus usuários ou onde outros serviços relacionados estão hospedados pode otimizar a latência e os custos. Manter uma convenção de nomenclatura clara para os recursos (ex: `rg-dio-appplatform-prod`) facilita a gestão.

### Criação do Servidor SQL e Banco de Dados SQL

Com o Grupo de Recursos criado, o próximo passo é provisionar um Servidor SQL Lógico e, dentro dele, o Banco de Dados SQL.

1.  **Servidor SQL Lógico:** Atua como um ponto administrativo central para um conjunto de bancos de dados. Ele gerencia logins, regras de firewall, regras de auditoria, etc.
2.  **Banco de Dados SQL:** O banco de dados em si, onde nossos dados de produtos serão armazenados.

Novamente, usando a Azure CLI:

```bash
# Exemplo de comando Azure CLI para criar um Servidor SQL
# Substitua <nome-do-servidor-sql> (deve ser globalmente único), <nome-do-grupo-de-recursos>,
# <login-admin>, <senha-admin> e <localizacao>
az sql server create \
    --name <nome-do-servidor-sql> \
    --resource-group <nome-do-grupo-de-recursos> \
    --location <localizacao> \
    --admin-user <login-admin> \
    --admin-password <senha-admin>

# Exemplo de comando Azure CLI para criar um Banco de Dados SQL
# Substitua <nome-do-banco-de-dados>, <nome-do-grupo-de-recursos>,
# <nome-do-servidor-sql> e <nome-da-sku> (ex: Basic, S0, GP_Gen5_1)
az sql db create \
    --resource-group <nome-do-grupo-de-recursos> \
    --server <nome-do-servidor-sql> \
    --name <nome-do-banco-de-dados> \
    --edition Basic # Ou outra SKU apropriada para o seu caso
```

**Insight:** A escolha da SKU (nível de serviço e desempenho) do Banco de Dados SQL impacta diretamente no custo e na capacidade. Para um projeto de aprendizado ou desenvolvimento inicial, SKUs mais básicas como 'Basic' ou 'S0' costumam ser suficientes. É crucial configurar regras de firewall no Servidor SQL para permitir o acesso a partir dos IPs necessários (como o da sua máquina de desenvolvimento ou do serviço que hospedará a aplicação).

Com esses passos, teríamos a infraestrutura básica de banco de dados pronta no Azure para a aplicação.



## Etapa 2: Criando a Conta de Armazenamento (Storage Account)

Para armazenar as imagens dos produtos, utilizaremos o Azure Blob Storage, que faz parte do serviço Azure Storage Account. Uma Conta de Armazenamento fornece um namespace exclusivo no Azure para seus dados, acessível globalmente via HTTP ou HTTPS.

### Criação da Conta de Armazenamento

Assim como os outros recursos, a Conta de Armazenamento pode ser criada via Azure CLI:

```bash
# Exemplo de comando Azure CLI para criar uma Storage Account
# Substitua <nome-da-conta-storage> (deve ser globalmente único, letras minúsculas e números),
# <nome-do-grupo-de-recursos>, <localizacao> e <sku-storage> (ex: Standard_LRS, Standard_GRS)
az storage account create \
    --name <nome-da-conta-storage> \
    --resource-group <nome-do-grupo-de-recursos> \
    --location <localizacao> \
    --sku Standard_LRS \
    --kind StorageV2 # Recomendado para a maioria dos cenários
```

**Insight:** O nome da Conta de Armazenamento é usado na URL de acesso aos blobs (ex: `https://<nome-da-conta-storage>.blob.core.windows.net`), por isso precisa ser único globalmente. A SKU define a redundância (LRS = Localmente Redundante, GRS = Geo-Redundante, etc.) e o nível de desempenho. `Standard_LRS` é geralmente a opção mais econômica para desenvolvimento e testes.

### Criação do Contêiner de Blob

Dentro da Conta de Armazenamento, os blobs (arquivos) são organizados em contêineres. Precisamos criar um contêiner para as imagens dos produtos.

```bash
# Exemplo de comando Azure CLI para criar um Contêiner de Blob
# Requer a connection string ou autenticação via login
# Obtenha a connection string: az storage account show-connection-string --name <nome-da-conta-storage> --resource-group <nome-do-grupo-de-recursos> --query connectionString

# Comando para criar o contêiner (usando connection string)
# Substitua <nome-do-container> e <connection-string-storage>
az storage container create \
    --name <nome-do-container> \
    --connection-string "<connection-string-storage>" \
    --public-access blob # Ou 'off' se o acesso anônimo não for desejado
```

**Insight:** O nível de acesso público (`--public-access`) define se os blobs dentro do contêiner podem ser acessados anonimamente pela internet. Para imagens de produtos que precisam ser exibidas em uma aplicação web pública, `blob` pode ser uma opção conveniente, mas considere as implicações de segurança. Para cenários mais restritos, manter o acesso `off` e usar Shared Access Signatures (SAS) ou autenticação via Azure AD para controlar o acesso é mais seguro.

Com a Conta de Armazenamento e o contêiner criados, temos o local para guardar as imagens dos produtos na nuvem.



## Etapa 3: Configurando o Banco de Dados e Criando a Tabela de Produtos

Após provisionar o Banco de Dados SQL no Azure, precisamos configurá-lo para permitir conexões e criar a estrutura de tabela necessária para armazenar os dados dos produtos.

### Configuração do Firewall

Por padrão, o Servidor SQL no Azure bloqueia todas as conexões externas. É fundamental adicionar regras de firewall para permitir o acesso a partir dos endereços IP que precisarão se conectar (por exemplo, o IP da sua máquina de desenvolvimento ou o IP de saída do serviço onde a aplicação será hospedada).

```bash
# Exemplo de comando Azure CLI para adicionar uma regra de firewall
# Permite acesso de um IP específico
# Substitua <nome-do-grupo-de-recursos>, <nome-do-servidor-sql>,
# <nome-da-regra> (descritivo), <ip-inicial> e <ip-final>
az sql server firewall-rule create \
    --resource-group <nome-do-grupo-de-recursos> \
    --server <nome-do-servidor-sql> \
    --name <nome-da-regra> \
    --start-ip-address <ip-inicial> \
    --end-ip-address <ip-final>

# Para permitir acesso de serviços do Azure (se a app for hospedada no Azure)
az sql server firewall-rule create \
    --resource-group <nome-do-grupo-de-recursos> \
    --server <nome-do-servidor-sql> \
    --name AllowAzureServices \
    --start-ip-address 0.0.0.0 \
    --end-ip-address 0.0.0.0
```

**Insight:** Gerenciar regras de firewall é crucial para a segurança. Evite abrir o acesso para `0.0.0.0` a `255.255.255.255` (qualquer IP) a menos que seja absolutamente necessário e temporário. A opção `AllowAzureServices` é mais segura para permitir que outros serviços Azure acessem o banco.

### Criação da Tabela de Produtos

Com o acesso liberado, podemos nos conectar ao banco de dados (usando ferramentas como SQL Server Management Studio, Azure Data Studio ou bibliotecas de código como `pyodbc` ou `pymssql`) e executar o script SQL para criar a tabela `Produtos`.

```sql
-- Exemplo de script SQL para criar a tabela Produtos

IF NOT EXISTS (SELECT * FROM sys.objects WHERE object_id = OBJECT_ID(N'[dbo].[Produtos]') AND type in (N'U'))
BEGIN
CREATE TABLE [dbo].[Produtos](
    [ProdutoId] [int] IDENTITY(1,1) NOT NULL,
    [Nome] [nvarchar](100) NOT NULL,
    [Descricao] [nvarchar](500) NULL,
    [Preco] [decimal](18, 2) NOT NULL,
    [ImagemUrl] [nvarchar](1024) NULL, -- Armazena a URL do blob da imagem
    [DataCadastro] [datetime] DEFAULT GETDATE(),
 CONSTRAINT [PK_Produtos] PRIMARY KEY CLUSTERED 
(
    [ProdutoId] ASC
)WITH (STATISTICS_NORECOMPUTE = OFF, IGNORE_DUP_KEY = OFF, OPTIMIZE_FOR_SEQUENTIAL_KEY = OFF) ON [PRIMARY]
) ON [PRIMARY]
END
GO

-- Opcional: Adicionar alguns dados de exemplo
-- INSERT INTO Produtos (Nome, Descricao, Preco, ImagemUrl) VALUES ('Produto Teste', 'Descrição do Produto Teste', 19.99, NULL);
```

**Insight:** Definir um `ProdutoId` como `IDENTITY` simplifica a geração de chaves primárias únicas. Armazenar a `ImagemUrl` (o link para o blob no Storage Account) em vez da imagem binária diretamente no banco de dados é uma prática recomendada para desempenho e escalabilidade, especialmente para bancos de dados relacionais.

Com a tabela criada, o banco de dados está pronto para receber os dados da aplicação.



## Etapa 4: Implementando o Salvamento de Imagens no Blob Storage (Python)

Com a infraestrutura do Azure pronta (SQL Database e Blob Storage), o próximo passo é implementar a lógica na aplicação Python para fazer o upload das imagens enviadas pelo usuário para o contêiner de Blob que criamos.

### Conectando ao Blob Storage

A biblioteca `azure-storage-blob` para Python facilita a interação com o serviço. A conexão geralmente é feita usando a *connection string* da Conta de Armazenamento.

```python
# Exemplo de código Python para conectar ao Blob Storage

import os
from azure.storage.blob import BlobServiceClient, BlobClient, ContainerClient

# Obtenha a connection string (idealmente de variáveis de ambiente ou configuração segura)
connect_str = os.getenv('AZURE_STORAGE_CONNECTION_STRING') # Exemplo buscando de variável de ambiente
container_name = "produtos" # Nome do contêiner criado anteriormente

try:
    # Criar o BlobServiceClient
    blob_service_client = BlobServiceClient.from_connection_string(connect_str)

    print(f"Conectado com sucesso à conta de armazenamento.")
    # (Opcional) Verificar se o contêiner existe ou criá-lo se necessário
    try:
        container_client = blob_service_client.get_container_client(container_name)
        container_client.get_container_properties() # Tenta obter propriedades para verificar existência
        print(f"Contêiner '{container_name}' já existe.")
    except Exception as e:
        print(f"Contêiner '{container_name}' não encontrado, criando... {e}")
        # container_client = blob_service_client.create_container(container_name)
        # print(f"Contêiner '{container_name}' criado.")
        # Nota: A criação pode falhar se as permissões não estiverem corretas.

except Exception as ex:
    print('Erro ao conectar ao Azure Storage:')
    print(ex)

```

**Insight:** É uma péssima prática de segurança embutir a *connection string* diretamente no código. Utilize variáveis de ambiente, Azure Key Vault ou outras soluções de gerenciamento de segredos para armazená-la de forma segura.

### Fazendo o Upload do Arquivo

Uma vez conectado, o processo de upload envolve obter o fluxo de bytes do arquivo enviado (por exemplo, através de um formulário web com Streamlit) e passá-lo para o `BlobClient`.

```python
# Exemplo de código Python para fazer upload de um arquivo para o Blob Storage

import os
import uuid # Para gerar nomes de arquivo únicos
from azure.storage.blob import BlobServiceClient

# ... (conexão com BlobServiceClient como no exemplo anterior) ...

# Supondo que 'uploaded_file' seja um objeto de arquivo obtido de um upload
# (ex: de st.file_uploader em Streamlit)

if uploaded_file is not None:
    # Ler os bytes do arquivo
    file_bytes = uploaded_file.read()
    
    # Gerar um nome de blob único para evitar sobrescritas
    # Usar a extensão original do arquivo
    file_extension = os.path.splitext(uploaded_file.name)[1]
    blob_name = f"{uuid.uuid4()}{file_extension}"
    
    try:
        # Criar um BlobClient para o novo blob
        blob_client = blob_service_client.get_blob_client(container=container_name, blob=blob_name)
        
        # Fazer o upload dos bytes
        blob_client.upload_blob(file_bytes, blob_type="BlockBlob")
        
        # Obter a URL do blob recém-criado para salvar no banco de dados
        blob_url = blob_client.url
        print(f"Upload bem-sucedido! URL do Blob: {blob_url}")
        
        # AGORA, você salvaria a blob_url na coluna ImagemUrl da tabela Produtos no SQL Database
        # junto com os outros dados do produto.
        
    except Exception as e:
        print(f"Erro durante o upload para o blob: {e}")

```

**Insight:** Gerar nomes de arquivo únicos (usando UUID, por exemplo) é crucial para evitar que um upload sobrescreva o arquivo de outro produto. Armazenar a URL completa do blob (`blob_client.url`) no banco de dados simplifica a recuperação e exibição da imagem na aplicação posteriormente.

Com esta lógica implementada, a aplicação seria capaz de receber um arquivo de imagem, enviá-lo para o Azure Blob Storage e obter a URL para referência futura.



## Etapa 5: Finalizando o Projeto - Integração e Aplicação Streamlit

Com os componentes individuais configurados (Banco de Dados SQL, Blob Storage) e a lógica de upload implementada, a etapa final é integrar tudo em uma aplicação funcional. O repositório de referência utiliza Python com a biblioteca Streamlit para criar uma interface web simples para o cadastro de produtos.

### Integrando Banco de Dados e Blob Storage na Aplicação

A aplicação Streamlit precisa:

1.  **Apresentar um Formulário:** Usar componentes do Streamlit (`st.text_input`, `st.text_area`, `st.number_input`, `st.file_uploader`) para coletar os dados do produto (nome, descrição, preço) e a imagem.
2.  **Processar o Upload da Imagem:** Ao receber um arquivo, executar a lógica da Etapa 4 para fazer o upload para o Azure Blob Storage e obter a `blob_url`.
3.  **Inserir Dados no SQL Database:** Conectar-se ao Banco de Dados SQL (usando bibliotecas como `pymssql` ou `pyodbc` e as credenciais configuradas) e executar um comando `INSERT` na tabela `Produtos`, incluindo a `blob_url` obtida no passo anterior.
4.  **Fornecer Feedback:** Exibir mensagens de sucesso ou erro para o usuário.

```python
# Exemplo (simplificado) de integração no Streamlit (main.py)

import streamlit as st
import pymssql
import os
import uuid
from azure.storage.blob import BlobServiceClient

# --- Configurações (Carregar de forma segura!) ---
DB_SERVER = os.getenv('DB_SERVER')
DB_DATABASE = os.getenv('DB_DATABASE')
DB_USERNAME = os.getenv('DB_USERNAME')
DB_PASSWORD = os.getenv('DB_PASSWORD')
AZURE_STORAGE_CONNECTION_STRING = os.getenv('AZURE_STORAGE_CONNECTION_STRING')
CONTAINER_NAME = "produtos"

# --- Funções Auxiliares ---
def upload_to_blob(file_bytes, file_extension):
    blob_service_client = BlobServiceClient.from_connection_string(AZURE_STORAGE_CONNECTION_STRING)
    blob_name = f"{uuid.uuid4()}{file_extension}"
    blob_client = blob_service_client.get_blob_client(container=CONTAINER_NAME, blob=blob_name)
    blob_client.upload_blob(file_bytes, blob_type="BlockBlob")
    return blob_client.url

def insert_product(nome, descricao, preco, imagem_url):
    conn = pymssql.connect(server=DB_SERVER, user=DB_USERNAME, password=DB_PASSWORD, database=DB_DATABASE)
    cursor = conn.cursor()
    sql = "INSERT INTO Produtos (Nome, Descricao, Preco, ImagemUrl) VALUES (%s, %s, %d, %s)"
    cursor.execute(sql, (nome, descricao, preco, imagem_url))
    conn.commit()
    conn.close()

# --- Interface Streamlit ---
st.title("Cadastro de Produto - E-Commerce na Cloud")

with st.form("product_form", clear_on_submit=True):
    product_name = st.text_input("Nome do Produto")
    description = st.text_area("Descrição do Produto")
    price = st.number_input("Preço do Produto", min_value=0.0, format="%.2f")
    uploaded_file = st.file_uploader("Imagem do Produto", type=["png", "jpg", "jpeg"])
    
    submitted = st.form_submit_button("Cadastrar Produto")

    if submitted:
        if product_name and price is not None and uploaded_file is not None:
            try:
                st.write("Processando cadastro...")
                # 1. Upload da imagem
                file_bytes = uploaded_file.read()
                file_extension = os.path.splitext(uploaded_file.name)[1]
                blob_url = upload_to_blob(file_bytes, file_extension)
                st.write(f"Imagem enviada para: {blob_url}")
                
                # 2. Inserção no banco
                insert_product(product_name, description, price, blob_url)
                
                st.success("Produto cadastrado com sucesso!")
            except Exception as e:
                st.error(f"Erro ao cadastrar produto: {e}")
        else:
            st.warning("Por favor, preencha todos os campos obrigatórios e anexe uma imagem.")

```

**Insight:** Este código é um exemplo simplificado. Uma aplicação real exigiria tratamento de erros mais robusto, validação de dados mais completa, gerenciamento de estado e, potencialmente, uma arquitetura mais desacoplada (por exemplo, usando uma API backend em vez de lógica direta no Streamlit). A segurança das credenciais é primordial.

### Executando a Aplicação

Para rodar localmente, seria necessário instalar as dependências (`pip install -r requirements.txt`, onde `requirements.txt` conteria `streamlit`, `pymssql`, `azure-storage-blob`) e executar `streamlit run main.py` no terminal, após configurar as variáveis de ambiente com as credenciais corretas.
